1. INTRODUCTION                                   *ansible-vault-introduction*

ansible-vault provides transparent editing of ansible-vault encrypted
files and inline `!vault` YAML secrets. All cryptography is delegated to the
`ansible-vault` CLI, which must be on $PATH. Requires Neovim >= 0.12.

Vault-encrypted files (first line `$ANSIBLE_VAULT;...`) are decrypted when
read and re-encrypted when written. Inline `!vault` blocks are edited in a
floating window and re-encrypted in place.

2. SETUP                                          *ansible-vault-setup*

The plugin works out of the box with defaults. To configure: >lua

  require("ansible-vault").setup({
    password = nil,
    password_file = nil,
    env_password_var = "ANSIBLE_VAULT_PASSWORD",
    env_password_file_var = "ANSIBLE_VAULT_PASSWORD_FILE",
    password_file_name = ".vault-password",
    dotenv_name = ".env",
    prompt = true,
    cache_ttl = 900,
    vault_id = nil,
    auto_decrypt = true,
    keymap_filetypes = { "yaml", "yaml.ansible" },
    inline = {
      enabled = true,
      treesitter = true,
      hover = true,
      float = { max_width = 0.6, max_height = 0.6, border = "rounded" },
    },
    picker = {
      enabled = true,
      backend = "auto",
    },
    conceal = {
      enabled = true,
      atomic = true,
    },
    keymaps = {
      toggle = "<leader>avv",
      toggle_buffer = "<leader>avV",
      edit_secret = "<leader>ave",
      reveal_buffer = "<leader>avE",
      find_buffer = "<leader>avf",
      find_project = "<leader>avF",
      rekey_secret = "<leader>avk",
      rekey_file = "<leader>avK",
      group = "ansible vault",
    },
    snacks = {
      explorer = true,
      icons = true,
    },
  })
<
Options ~

  password              Vault password, set directly. Use with care.
  password_file         Path to a vault password file or executable script.
  env_password_var      Environment variable holding the password itself.
  env_password_file_var Environment variable holding a password file path.
  password_file_name    File name(s) discovered walking up from the edited
                        file. Default: { ".vault-password", ".vault_pass",
                        ".vault-pass" }.
  dotenv_name           Dotenv file name discovered the same way.
  prompt                Prompt interactively when nothing else resolves.
  cache_ttl             Seconds prompted passwords are cached (0 disables).
  vault_id              Default vault-id label for new encryptions.
  vault_ids             Per-vault-id password sources, e.g. >lua
                        vault_ids = { prod = { password_file = "~/.v-prod" } }
<
  confirm_default       Ask which vault-id to use for every new encryption
                        (default true). When false, the default (vault_id or
                        unlabeled) is used silently and the picker only
                        appears when identities are known.
  confirm_decrypt       Ask for authorization before auto-decrypting a vault
                        file on open (default true), since the plaintext may
                        be sensitive. When false, vault files decrypt
                        immediately. Only applies with auto_decrypt on.
  auto_decrypt          Transparently decrypt vault files on read.
  keymap_filetypes      Filetypes whose buffers get the keymaps (buffer-
                        local). Default: { "yaml", "yaml.ansible" }.
  inline.enabled        Enable inline `!vault` editing.
  inline.editor         Value editor for |:AnsibleVaultEdit|: "auto" uses
                        |vim.ui.input()| (snacks.input when installed) for
                        single-line values and the floating editor for
                        multi-line values; "input" or "float" forces one
                        (multi-line values always use the float).
  inline.treesitter     Use tree-sitter (YAML parser) to reject false-positive
                        `!vault` matches (e.g. inside block scalars or
                        comments) when a parser is available. Falls back to
                        line-based detection otherwise.
  inline.hover          Map K to a decrypted read-only preview of the vault
                        block under the cursor. Falls back to default K
                        elsewhere; buffer-local (e.g. LSP) K mappings take
                        precedence over this global mapping.
  inline.float          Floating window sizing (fractions of the editor) and
                        border style.
  picker.enabled        Enable the secret picker.
  picker.backend        "auto" (snacks, then telescope, then vim.ui.select),
                        or force one of "snacks", "telescope", "select".
  conceal.enabled       Conceal the hex body of inline `!vault` blocks behind
                        a "[vault]" marker (uses conceal_lines extmarks;
                        'conceallevel' is raised per window while it shows a
                        concealed buffer and restored afterwards).
  conceal.atomic        The `!vault |` token on the key line stands for the
                        hidden blob (default true):
                        - the blob is shown only while the cursor is on the
                          token;
                        - the cursor never rests on blob lines; the token acts
                          like one character (landing inside it snaps to its
                          start, moving forward off it jumps past the block);
                        - breaking the token (`x`, `dw`, `D`, `C`, ...) or
                          deleting the key line removes the blob as well; a
                          single |u| restores both;
                        - `dd` on the key line deletes and yanks the whole
                          block, `o` opens the new line below it, and lines
                          put between a key and its blob move below the blob.
  keymaps.toggle        Encrypt the plaintext under the cursor / decrypt the
                        block under the cursor (default <leader>avv).
  keymaps.toggle_buffer Encrypt/decrypt the whole buffer by state
                        (default <leader>avV).
  keymaps.edit_secret   |:AnsibleVaultEdit| (default <leader>ave).
  keymaps.reveal_buffer |:AnsibleVaultReveal| (default <leader>avE).
  keymaps.find_buffer   |:AnsibleVaultSecrets| (default <leader>avf).
  keymaps.find_project  |:AnsibleVaultFiles| (default <leader>avF). Global:
                        works from any buffer inside an ansible project.
  keymaps.rekey_secret  Rekey the secret under the cursor (default <leader>avk).
  keymaps.rekey_file    |:AnsibleVaultRekey| (default <leader>avK).
  keymaps.group         which-key group labels keyed by prefix (default:
                        { ["<leader>a"] = "ansible", ["<leader>av"] = "vault" }).
                        With lazy.nvim the installer contributes them to
                        which-key's opts.spec (see which_key_spec());
                        otherwise setup() registers them via wk.add (queued
                        pre-load, or directly inserted post-load).
  snacks.explorer       Add encrypt/decrypt file actions (bound to
                        keymaps.encrypt_file/decrypt_file) to the snacks
                        explorer (default true).
  snacks.icons          Show a lock icon for vault-encrypted files in snacks
                        pickers (default true).

3. PASSWORDS                                      *ansible-vault-passwords*

For a given vault-id, id-specific sources win; otherwise the default chain
applies (mirroring ansible, which tries every available secret):

  1. `vault_ids[id]` from setup()
  2. `vault_identity_list` (ansible.cfg via $ANSIBLE_CONFIG or discovered
     walking up, or $ANSIBLE_VAULT_IDENTITY_LIST)
  3. `password` from setup()
  4. $ANSIBLE_VAULT_PASSWORD
  5. `password_file` from setup()
  6. $ANSIBLE_VAULT_PASSWORD_FILE
  7. `vault_password_file` from ansible.cfg
  8. `.env` files walking up from the file's directory
     (ANSIBLE_VAULT_PASSWORD or ANSIBLE_VAULT_PASSWORD_FILE)
  9. `.vault-password` / `.vault_pass` / `.vault-pass` files walking up the
     same way
  10. Interactive prompt

Identity list entries look like `prod@~/.vault-pass-prod`, `dev@script.sh`,
or `stag@prompt` (interactive, cached per directory). Relative paths resolve
against the ansible.cfg location. Executable password scripts are run by
ansible-vault itself, so password-manager integrations work.

When creating new ciphertext the label is chosen as follows: an explicit
[vault-id] command argument always wins (any label is accepted; known ids
are offered by completion). Otherwise, with `confirm_default` (default
true), every encryption flow asks: the default — "(default)", or "(default:
id)" when vault_id is set — plus all known ids and "(new id…)". With
`confirm_default = false` the default is used silently and the picker only
appears when identities are known. A bang on the encrypt commands skips all
password sources and asks for a one-off password. Existing ciphertext
always keeps its own label when re-encrypted.

The upward search never considers the home directory. Prompted passwords are
cached in memory only, scoped per directory tree. Raw passwords are passed
to ansible-vault via a 0600 temp file deleted after each call.

4. COMMANDS                                       *ansible-vault-commands*

                                                        *:AnsibleVaultEdit*
:AnsibleVaultEdit       Decrypt the `!vault` block under the cursor into a
                        floating window. Writing the float (:w or <CR>)
                        re-encrypts and replaces the block; <Esc>/q cancels.

                                                     *:AnsibleVaultSecrets*
:AnsibleVaultSecrets    List all `!vault` secrets in the current buffer and
                        open the chosen one in the edit float. Uses
                        snacks.nvim or telescope.nvim when installed, falling
                        back to |vim.ui.select()|.

                                                      *:AnsibleVaultReveal*
:AnsibleVaultReveal     Toggle reveal mode: decrypt every `!vault` block in
                        the buffer into editable plaintext lines (a
                        `key: value` line, or a `key: |-` literal block for
                        multi-line values). While revealed the buffer is
                        acwrite: `:w` re-encrypts each secret and writes only
                        ciphertext to disk, the buffer keeps the plaintext
                        view. Toggle again to re-encrypt the blocks in the
                        buffer. Blocks that fail to decrypt stay encrypted;
                        writes abort with an error rather than risking
                        corruption.

                                                *:AnsibleVaultEncryptString*
:[range]AnsibleVaultEncryptString[!] [vault-id]
                        Encrypt [range] lines into a `key: !vault |` block.
                        Prompts for the variable name; a single `key: value`
                        line pre-fills the key and encrypts only the value.
                        The optional [vault-id] argument (or the vault_id
                        option) labels the new secret; any label is accepted
                        and known ids are offered by completion. With a bang
                        (!) all password sources and the cache are skipped
                        and a one-off password is requested.

                                                     *:AnsibleVaultDecrypt*
:AnsibleVaultDecrypt    Decrypt the current buffer in place. The buffer is
                        re-encrypted on write.

                                                      *:AnsibleVaultEncrypt*
:AnsibleVaultEncrypt[!] [vault-id]
                        Encrypt the current buffer, replacing its content
                        with vault ciphertext. The optional [vault-id]
                        argument (or the vault_id option) labels the file;
                        any label is accepted and known ids are offered by
                        completion. With a bang (!) all password sources and
                        the cache are skipped and a one-off password is
                        requested. The prompted password replaces any cached
                        entry for that vault-id and directory.

                                                *:AnsibleVaultDecryptString*
:AnsibleVaultDecryptString
                        Decrypt the `!vault` block under the cursor back to
                        plaintext in place (`key: value`, or a `key: |-`
                        literal block for multi-line values). Nothing is
                        re-encrypted: the value stays plaintext until you
                        encrypt it again. The inverse of
                        |:AnsibleVaultEncryptString|.

                                                       *:AnsibleVaultToggle*
:AnsibleVaultToggle     One-key round trip: decrypt the `!vault` block under
                        the cursor (like |:AnsibleVaultDecryptString|), or
                        encrypt the plaintext value/line under the cursor
                        (like |:AnsibleVaultEncryptString| on the current
                        line). A `key: value` line keeps its key without
                        asking, so with `confirm_default = false` and a
                        password source it encrypts with no prompt at all.

                                                        *:AnsibleVaultFiles*
:AnsibleVaultFiles      Search the project for vault secrets: inline `!vault`
                        blocks in yaml files (file:line key) and whole-file
                        encrypted files (hidden dirs and common noise like
                        .git/node_modules are skipped). Picking an inline
                        secret jumps to it and opens the edit float; picking
                        a file edits it (transparent decrypt on read). Uses
                        snacks/telescope/vim.ui.select per picker.backend.

                                                       *:AnsibleVaultRekey*
:AnsibleVaultRekey      Rekey the vault file backing the current buffer:
                        prompts for a new password and optionally a new
                        vault-id (an existing vault-id label is preserved).
                        The in-memory password cache is cleared afterwards;
                        update your password file/env to the new password.

                                                   *:AnsibleVaultClearCache*
:AnsibleVaultClearCache Forget all cached (prompted) vault passwords.

5. STATUSLINE                                     *ansible-vault-statusline*

                                                *ansible-vault.status()*
require("ansible-vault").status({buf})
                        Returns "[vault]" or "[vault:<id>]" for vault-related
                        buffers, "" otherwise. Cached per buffer (invalidated
                        on change), safe to call on every redraw. Example with
                        lualine: >lua
                          sections = { lualine_x = { { require("ansible-vault").status } } }
<

6. HIGHLIGHTS                                     *ansible-vault-highlights*

The edit float maps these groups (default links shown; override freely):

  AnsibleVaultTitle    -> Title       float title ("vault: <key>")
  AnsibleVaultFooter   -> Special     footer key hints
  AnsibleVaultBorder   -> FloatBorder float border

The float content gets filetype=yaml for basic syntax coloring.

7. MAPPINGS                                       *ansible-vault-mappings*

All vault operations live under the <leader>av (ansible vault) prefix,
chosen to coexist with LazyVim defaults and with mfussenegger/nvim-ansible.
Lowercase keys act on the secret under the cursor, uppercase on the buffer.

The keymaps below are buffer-local to |keymap_filetypes| buffers (yaml by
default), so they never clash with mappings in unrelated buffers. The only
exception is <leader>avF: it is global and works from any buffer when the
current file is inside an ansible project (detected via ansible.cfg,
group_vars/, host_vars/, playbooks/, or roles/).

<leader>avv             |:AnsibleVaultToggle| (keymaps.toggle)
<leader>avV             Encrypt/decrypt buffer by state (keymaps.toggle_buffer)
<leader>ave             |:AnsibleVaultEdit| (keymaps.edit_secret)
<leader>avE             |:AnsibleVaultReveal| (keymaps.reveal_buffer)
<leader>avf             |:AnsibleVaultSecrets| (keymaps.find_buffer)
<leader>avF             |:AnsibleVaultFiles| (keymaps.find_project; global,
                        guarded by ansible project detection)
<leader>avk             Rekey the secret under the cursor (keymaps.rekey_secret)
<leader>avK             |:AnsibleVaultRekey| (keymaps.rekey_file)
K                       Decrypted preview of the block under the cursor
                        (inline.hover; global, but buffer-local mappings such
                        as LSP hover take precedence; default K elsewhere)

In the snacks explorer (snacks.explorer):
<leader>avV             Encrypt/decrypt the file under the cursor (in place,
                        on disk, dispatched by state)

Inside the edit float:
<CR>                    Save and re-encrypt
<Esc>, q                Cancel without changes
